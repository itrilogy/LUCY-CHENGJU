# arrow (进度控制/双代号网络图) 协议切片

## 1. 专家灵魂 (The Soul)

### 双代号网络图 (Arrow Diagram Method)

矢线图，又称双代号网络图 (ADM)，是计划管理的重要工具。它通过节点（事件）和箭条（工作）展示各项任务间的先后顺序与时间关联。

#### 核心计算逻辑 (CPM)

- **关键路径 (Critical Path)**：项目中耗时最长的路径。任何延迟都会导致整个项目的延期。
- **宽裕时间 (Float)**：通过 ES/LS 计算每个节点的时差。
- **虚任务 (Dummy Task)**：仅表示任务间逻辑依赖关系的虚线，**工期恒为 0**。

> [!TIP]
> **资源优化**：识别非关键路径上的时差 (Float)，平衡峰值期间的人力或设备资源。

## 2. 语法血肉 (The Flesh)

### IQS-DSL v1 — arrow (Network)

| 语法 | 说明 | 示例 |
| :--- | :--- | :--- |
| `Title:` | 项目名称（图标题） 形如 `<文本>` **必填** | `Title: 新生产线建设` |
| `ShowCritical:` | 是否高亮关键路径（true / false） | `ShowCritical: true` |
| `ShowShortest:` | 是否高亮最短路径（true / false） | `ShowShortest: false` |
| `Color[Node | Line | Critical | Shortest]` | #HEX 颜色：节点 / 连线 / 关键路径高亮 / 最短路径高亮 | `Color[Critical]: #E74C3C` |
| `Event:` | 节点（事件）定义；ID 为**整数**，供任务行引用 形如 `<ID>, <标签>` **必填** | `Event: 1, 立项完成` |
| `实任务:` | 带工期的实际工作（用 `->`） 形如 `<SrcID> -> <TgtID>: <工期>, <名称>` **必填** | `1 -> 2: 3, 需求分析` |
| `虚任务:` | 仅表达逻辑依赖的虚线（用 `..>`），**工期固定 0** 形如 `<SrcID> ..> <TgtID>: 0, <名称>` | `5 ..> 4: 0, 依赖同步` |

### 边界说明

- **`Event`**：ID 建议用连续整数；每个 ID 只能定义一次。
- **`实任务`**：工期为**正数**（单位自定，通常为天）；名称可省略。`->` 与 `..>` 不可混用。
- **`虚任务`**：用于表达「同一对节点间需要多条并行逻辑」或修正跨层级依赖；工期写非 0 不报错但语义无效。

### 反例（错 → 对）

- 错：`1 -> 2: 0, 依赖同步`
  对：`1 ..> 2: 0, 依赖同步`
  因：零工期的逻辑依赖应写成虚任务 `..>`；用 `->` 会被当作实任务参与关键路径计算。
- 错：`1 -> 2: 3天, 需求分析`
  对：`1 -> 2: 3, 需求分析`
  因：工期须为纯数值；单位写在标签里或图标题中，不要混进数值字段。
- 错：`2 -> 3: 2, 架构方案   （而未定义 Event: 2）`
  对：`Event: 2, 需求评审\n2 -> 3: 2, 架构方案`
  因：任务两端的事件 ID 必须先由 `Event:` 定义。
- 错：````dsl\nTitle: xxx\n````
  对：`Title: xxx`
  因：禁止 Markdown 代码围栏 —— 只输出纯文本 DSL。
- 错：`{"Title": "xxx"}`
  对：`Title: xxx`
  因：`dsl` 必须是纯文本字符串，不是 JSON 对象。
- 错：`这是根据您的需求生成的图表：\nTitle: xxx`
  对：`Title: xxx`
  因：禁止解释性前后缀。

## 3. 官方示例 (The Seed)

### 场景：办公软件 V1.0 开发计划

```dsl
Title: 办公软件 V1.0 开发计划
ShowCritical: true
ShowShortest: false

Color[Critical]: #E74C3C
Color[Line]: #00D2FF

// 节点（事件）
Event: 1, 立项完成
Event: 2, 需求评审
Event: 3, 架构设计
Event: 4, 模块 A 开发
Event: 5, 模块 B 开发
Event: 6, 集成测试
Event: 7, 交付

// 实任务：Src -> Tgt: 工期, 名称
1 -> 2: 3, 需求分析
2 -> 3: 2, 架构方案
3 -> 4: 10, A逻辑实现
3 -> 5: 8, B逻辑实现
4 -> 6: 5, 系统集成
6 -> 7: 2, 验收发布

// 虚任务：仅表达逻辑依赖，工期恒为 0
5 ..> 4: 0, 依赖同步
```

> 7 个事件 + 6 条实任务 + 1 条虚任务；关键路径由引擎按 CPM 自动求解并高亮。
