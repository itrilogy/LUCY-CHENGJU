# 源代码鉴别材料说明

> 依据计算机软件著作权登记对「源程序鉴别材料」的常见要求整理。  
> 具体页数、行数以版权中心当期《登记指南》为准。

---

## 1. 一般要求（惯例）

| 项 | 常见要求 |
|:---|:---|
| 页数 | 前连续 **30 页** + 后连续 **30 页**；不足 60 页则提交全部 |
| 每页行数 | 不少于 **50 行**（末页除外） |
| 内容 | 源程序正文；应连续、无双栏；可含少量注释 |
| 页眉 | 建议标注：软件全称、版本号 |
| 页脚 | 页码 |

---

## 2. 软著 A（DSL 图表引擎）建议选取范围

### 2.1 前 30 页（建议从「入口与核心类型」起连续摘录）

推荐打印顺序（按文件拼接后连续排版）：

1. `index.tsx`  
2. `App.tsx`（前部至中部）  
3. `types.ts`（前部）  
4. `constants.tsx`（前部）  
5. `dsl/kinds.json` 可改为摘录 `dsl/registry.ts` + `dsl/shell.ts` + `dsl/index.ts`  
6. `services/aiService.ts`  
7. 若干核心解析：`components/ControlChartEditor.tsx`、`ParetoEditor.tsx`、`FishboneEditor.tsx` 的 parse 段  

> 以「连续页」为准：选定起始文件后按目录顺序连续取足 30 页，避免只挑精华导致不连续。

### 2.2 后 30 页（建议取「渲染与复杂图」尾部）

推荐包含：

1. `components/MatrixDiagram.tsx`（后部）  
2. `components/ControlChart.tsx`（统计计算段）  
3. `components/ArrowDiagramEditor.tsx`（CPM 相关）  
4. `components/DashboardView.tsx` 或 `utils/exportUtils.ts`  

### 2.3 辅助统计（约数，供申请表）

- TypeScript/TSX/JS 主体合计约 **2.2 万行**（不含 `node_modules`）  
- 精确数以提交前 `cloc` 或 `find … | xargs wc -l` 为准  

---

## 3. 软著 B（MCP Server）建议选取范围

源码量较小，可 **提交全部** 主要源文件：

1. `mcp-server/index.js`（全文，优先）  
2. `mcp-server/package.json`  
3. `mcp-server/mcp_tools.json` **节选**前若干工具定义 + 后若干工具定义（JSON 过长时）  
4. 可选：`mcp-server/verify_tools.js`  

若必须凑页数，可附：

- `protocol/governance.md` 不作为「源程序」首选；优先保持 JS 源程序属性  

---

## 4. 排版与提交操作建议

```bash
# 示例：生成待打印文本（单位可改用 Word 另排）
# 1. 按选取列表 cat 拼接
# 2. 用编辑器设置等宽字体、每页 50 行
# 3. 导出 PDF 并加页眉页脚
```

**页眉示例：**

```text
智能质量控制工作站 DSL 图表引擎系统 V3.5  源程序
```

**注意：**

- 删除含真实 API Key、内网地址的片段，或替换为占位符  
- 勿提交 `node_modules`  
- 与申请表软件全称、版本号严格一致
