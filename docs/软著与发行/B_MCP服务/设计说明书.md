## 1. 引言

### 1.1 编写目的

阐明 IQS MCP Server 的架构、协议处理、渲染链路与部署方式，用于软件著作权登记与发行运维。

### 1.2 背景

大模型代理需要稳定、可发现的「画 QC 图」能力。直接把全部专家知识塞进工具描述会导致 Token 膨胀。本服务基于 **MCP**，采用 **瘦声明 + 按需资源** 与 **无头调用前端引擎** 的架构。

### 1.3 术语

| 术语 | 说明 |
|:---|:---|
| MCP | Model Context Protocol |
| Stdio | 标准输入输出传输（本地 IDE/桌面代理） |
| SSE | Server-Sent Events 传输（远程 HTTP） |
| ILDR | 通过页面桥接函数导出，而非简单截屏 |

## 2. 系统概述

### 2.1 目标

1. 向 AI 客户端暴露图表渲染工具；  
2. 控制 list_tools 体积（CORE 优先、描述瘦身）；  
3. 按需提供语法协议资源；  
4. 调用 IQS Web 引擎完成专业渲染并返回结果。

### 2.2 运行环境

- Node.js 20+  
- Puppeteer + Chromium/Chrome  
- 可访问的 IQS 前端基址 `IQS_BASE_URL`（默认 `http://localhost:12000`）  
- 可选 Docker 与 Compose 多端口暴露（12000 Web + 12001 MCP）

### 2.3 总体架构

```text
AI Client (Claude / Copilot / 自定义)
        │  MCP (stdio | sse)
        ▼
┌───────────────────────────┐
│  IQS MCP Server (Node)    │
│  · ListTools / CallTool   │
│  · List/Read Resources    │
│  · mcp_tools.json 配置    │
└───────────┬───────────────┘
            │ Puppeteer
            ▼
┌───────────────────────────┐
│  IQS Web Engine (Headless)│
│  DSL 解析 + 图表渲染      │
│  captureIQSChart 导出     │
└───────────────────────────┘
```

### 2.4 设计原则

1. **声明与知识分离**：list_tools 仅路由；语法在 resources。  
2. **CORE / RELIEF**：核心 QC 工具优先展示；扩展图种降级声明。  
3. **引擎复用**：不在 Node 侧重写绘图算法，复用前端专业实现。  
4. **输入防腐**：拒绝 JSON 对象充当 dsl，返回示例骨架。

## 3. 功能模块设计

### 3.1 服务启动与传输

- 入口：`mcp-server/index.js`  
- Stdio：默认，适配桌面代理  
- SSE：`--transport=sse`，Express + CORS，端口 `PORT`（默认 12001）  
- 静态：`/renders` 提供已保存 PNG 访问  

### 3.2 工具清单（ListTools）

- 读取 `mcp_tools.json`  
- 过滤 `sub_type === master`（master 仅用于拼接，不作为可调用工具）  
- 生成瘦描述：`[CORE|RELIEF] + 一句话 + intents + resource URI`  
- 排序：CORE 在前  
- 统一 inputSchema：`dsl: string`，可选 `width`/`height`

### 3.3 工具调用（CallTool）

1. 由工具名解析 `type`（mermaid / vchart / native kind）  
2. 检测非法 JSON 入参 → 错误回执 + 官方示例  
3. `renderChart(type, dsl, w, h, saveToFile)`  
4. Stdio 返回 base64 图片；SSE 可落盘并返回 URL  

### 3.4 资源（Resources）

| URI | 内容 |
|:---|:---|
| `protocol://governance` | 全局治理 |
| `protocol://dsl/v1` | DSL v1 摘要 |
| `protocol://segments` | 索引 |
| `protocol://segments/{parent}/{sub}` | Master + 子类专家逻辑 + 语法 + 示例 |
| `protocol://segments/{key}` | 兼容单文件切片 |

### 3.5 无头渲染

1. 启动 Chromium  
2. 打开 `{BASE_URL}/?mode=headless&type=&dsl=&theme=light`  
3. 等待 `IQS_READY`  
4. 调用 `captureIQSChart({ pixelRatio, width, height })`  
5. 关闭浏览器，返回数据  

### 3.6 配置数据

- `mcp_tools.json`：工具元数据（name、parent_type、sub_type、tier、expert_logic、syntax_rules、official_example…）  
- 环境变量：`IQS_BASE_URL`、`PORT`、`IQS_SERVER_PUBLIC_URL`

## 4. 接口设计

### 4.1 MCP 工具调用（逻辑接口）

**请求：**

```json
{
  "name": "render_control",
  "arguments": {
    "dsl": "Title: ...\nType: X-bar-R\n...",
    "width": 1200,
    "height": 800
  }
}
```

**成功：** image 内容或 Markdown 图片链接  
**失败：** 文本错误 + 可选修正示例  

### 4.2 SSE HTTP

| 路径 | 说明 |
|:---|:---|
| `GET /sse` | 建立 SSE MCP 会话 |
| `POST /messages?sessionId=` | 客户端消息 |
| `GET /renders/*` | 渲染文件 |

### 4.3 与引擎约定

依赖前端提供：

- `window.IQS_READY === true`  
- `window.captureIQSChart(options) => Promise<dataURL>`
