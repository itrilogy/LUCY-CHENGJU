## 3. 鱼骨图布局数学评估

### 3.1 现行算法的形式化描述

设问题树 $T=(V,E)$，大骨（Level 1）集合 $M=\{M_1,\dots,M_m\}$，第 $k$ 族子项数 $n_k$，孙项数 $g_k$。现行实现的五步：

$$
\begin{aligned}
&\text{(1) 权重}\quad w(v)=\begin{cases}1.0,& \text{叶}\\ \sum_{u\in \mathrm{ch}(v)} w(u)+0.6,&\text{否则}\end{cases}\\
&\text{(2) 大骨长}\quad L_k=\frac{\max(H_k,\,H_{k\oplus1},\,200)}{\sin 60^\circ},\quad H_k=\max(180,\ 140+48n_k+30g_k)\\
&\text{(3) 行锚点}\quad t_j=0.22+\frac{\sum_{i<j}w_i+w_j/2}{\sum_i w_i}\cdot 0.56\\
&\text{(4) 中骨长}\quad \ell_j=\max(65,\ W_{\text{text}}+30,\ 65+35g_j+W_{\text{text}})\\
&\text{(5) 族推进}\quad x_{p+1}=x_p+\max\Big(260,\ \max_{s\in\{t,b\}}R_s^{(p)}+\max_{s\in\{t,b\}}L_s^{(p+1)}+70\Big)
\end{aligned}
$$

其中 $k\oplus1$ 表示成对共轭大骨（$\lfloor k/2\rfloor$ 相同）。

### 3.2 定理 1（一维保序串联的紧性）—— 现状已最优的部分

**命题**：固定族的包络 $(L_k,R_k)$ 与净距 $G$，约束为「保序 $x_1<\dots<x_m$」+「区间互斥 $(x_{k+1}-R_{k+1})-(x_k+L_k)\ge G$」，则

$$x_k^{\min}=x_1+\sum_{j<k}\big(R_j+L_{j+1}+G\big)$$

**证明**：约束集是前向差分约束系统 $x_{k+1}-x_k\ge c_k$，其紧解即前缀和；任何更小解违反第 $k$ 个约束。∎

**推论（对用户方案的裁定）**：只要"每族在 X 轴投影必须互斥且保序"成立，**串联算法本身没有优化空间**。"族间隔过大"的感觉不是串联算法造成的，而是 ①每族 $L_k+R_k$ 本身被撑大（范式问题，AUD-180）；②成对绑定牺牲了维度（定理 2）；③$G=70$ 与尾部净距叠加；④最终 `fitView` 把一切等比例压小（AUD-176）。

### 3.3 定理 2（成对绑定是弱劣解，但收益有上界）

设第 $p$ 对上/下半区族包络 $(L^t_p,R^t_p),(L^b_p,R^b_p)$，令

$$W_{\text{pair}}=\sum_p\Big[\max(L^t_p,L^b_p)+\max(R^t_p,R^b_p)+G\Big],\quad
W_{\text{indep}}=\max\Big(\sum_p(L^t_p+R^t_p+G),\ \sum_p(L^b_p+R^b_p+G)\Big)$$

**命题**：$W_{\text{indep}}\le W_{\text{pair}}$。因 $\sum_p\max(a_p,b_p)\ge\max(\sum a_p,\sum b_p)$（逐项取大 ≥ 总和取大）。

**上界**：$\dfrac{W_{\text{pair}}-W_{\text{indep}}}{W_{\text{pair}}}\le \dfrac12$，等号在两半区总量相等且逐对需求完全互补时取得。

**实测**：8.5% / 0.0% / 2.1%（三用例）。⇒ **「分半区独立」是正确但收益有限的方向**；它真正价值不在省宽，而在**解耦**（下方族的复杂度不再顶推上方族的 X 位置，视觉上族对不再刚性对齐，也就是用户要的"剪刀状"）。

### 3.4 定理 3（包络口径低估）

**命题**：$\forall k$，`assumedMainLen` $=H_k/\sin60 \le L_k^{\text{actual}}$，故 $R_k$ 低估

$$\Delta R_k \approx t_{\max}\cdot\cos 60^\circ\cdot\big(L_k^{\text{actual}}-H_k/\sin60\big)$$

**实测**：A 用例「机」307→342（$\Delta R\approx 15$px）、B 用例「法」273→397（$\Delta R\approx 54$px）。当前由 $G=70$ 吸收，故断言 7 仍 PASS（实测净空 116.7px / 205.6px）；但**一旦按常规优化收紧 $G$，低估立刻转为真实重叠**。

**结论**：包络必须**两遍解算** —— 先定 $L_k^{\text{actual}}$（谐波或按需），再以实际 $\cos60\cdot L_k$ 重算 $(L_k,R_k)$，最后推进 X。这是"优化族间距"的前置条件，否则任何收紧都是不可证的。

### 3.5 定理 4（垂直自洽的必要条件）

设族内 $n$ 行中骨，相邻行 $j,j{+}1$ 的最大向下/向上子骨垂距 $d_j,u_{j+1}$，行高 $h$，净距 $\delta$。行距在骨上为 $\frac{t_{\text{span}}}{n-1}H$（$t_{\text{span}}=0.56$），故无碰撞必要条件：

$$H\ \ge\ \frac{n-1}{t_{\text{span}}}\cdot\max_{j}\big(d_j+u_{j+1}+h+\delta\big)$$

代入实测值（$d=u=36,\ h=15,\ \delta=6$）：$n=4$ 时需 $H\ge 498$px，而现行公式给出 $140+48\times4=332$px。**探针实测 rows=3..8 全部违反（行距 86.6/80.1/76.2/73.5/70.3px < 93px）**。

**为什么官方 4 骨用例没暴露**：相邻行不同时挂子骨（`人`族仅第 1 行有孙项），$d_j+u_{j+1}$ 远小于最坏值 —— 属于**样例侥幸**，不是结构保证。

**闭式收口**：把 $H_k$ 从"线性经验式"改为"由行需求反解"，$L_k=H_k/\sin60$ 自然跟随；此改动同时消解定理 3 的口径误差（两遍合一遍）。

### 3.6 定理 5（缩放闭环与"画布能装几族"）

`fitView` 后有效字号 $f_{\text{eff}}=f\cdot s$，$s=\min\!\big(\frac{W-2p}{W_c},\frac{H-2p}{H_c}\big)$。可读约束 $f_{\text{eff}}\ge f_{\min}$ 等价于

$$W_c\ \le\ (W-2p)\cdot\frac{f}{f_{\min}}\quad(\text{宽度主导时})$$

1200×800、$p=120$、$f=13$、$f_{\min}=10$ 时右端 $=1248$px。实测 $W_c=1558/2624/1436$ ⇒ 三个用例**全部不可行**。由此得"每画布可容纳族数"上限

$$m\ \le\ \frac{1248}{\overline{L+R}}\ \approx\ \frac{1248}{400}\approx 3.1$$

即**在 1200×800 上放 4 个以上大骨，必然跌破 10px 可读线** —— 这是纯几何结论，与实现无关。要容纳 5M1E 六骨可读，必须让 $\overline{L+R}\lesssim 208$px（under-line 范式 + 半区独立 + 标题框内嵌才能接近），否则应走"排版阶梯 + 输出更大画布"。

## 5. 对用户五步方案的逐条裁定

| 用户设想 | 数学裁定 | 建议 |
|:--|:--|:--|
| **① 按主骨分上半区/下半区，各自按层级深度从浅到深构造族** | ✅ 维度解耦正确（定理 2 严格不劣）。⚠️"从浅到深"与"按 DSL 顺序"（第 ② 步）**互相冲突** | 保留"半区自治"，但**排序只用 DSL 顺序**（保序 → 可复现、可 diff、语义稳定）；深度只进入 $H_k$ 反解，不参与 X 排序 |
| **② 按 DSL 顺序安置族** | ✅ 正确且必要（定理 1 保证保序下已是最紧一维解） | 采纳；建议在门禁中断言 `x_k` 单调递增，防回归 |
| **③ 遇遮挡即对相关族自适应生长** | ❌ **方向反了**：在"族=X 区间"模型下，"生长"增大 $L/R$ → 需要更大间距 → 正反馈，可能不收敛。而实测三用例**遮挡为 0**，不存在需要生长的情形 | 改为「**Y 向分带 + 行级区间互斥**」：把每族的中骨行投影到 lane，只有 Y 重叠的行才需 X 互斥（区间图着色），族级"生长"降级为兜底 |
| **④ 上下半区对应族在主骨上错位、不共点、剪刀状** | ✅ 现状仅 $2\delta=44$px 固定相位（断言 6 已 PASS），属"最小不共点"。数学上可加大到 $\delta=\frac12\min(\text{族宽})$ 而不引入新冲突（两半区 Y 分离，X 可自由交错） | 采纳，参数化 $\delta$ 并纳入断言：$40\le 2\delta\le \min(\text{族宽})$，且 $\delta$ 变化不得减少任何净空 |
| **⑤ 整体完成后按画布缩放** | ⚠️ 现状正是"先布局、后 `fitView`"，但**没有闭环**：缩放比不回馈排版，实测跌到 4.66px 仍不触发换行/缩字 | 采纳并加闭环：算完 $s$ 后若 $f\cdot s<f_{\min}$，**回到排版层**（换行/缩字/收紧 $G$）重排，最多 2 轮；仍不达标则输出 warning 并建议更大画布 |

## 6. 推荐算法（闭式、确定性、O(V+E)）—— ✅ 已按此实现于 `utils/fishboneGraph.ts`

```
Pass 0  排版决策（纯度量，不定位）
        对每个 label：estimateTextWidth → 三阶阶梯（单行 / 缩字 / 双行）
        范式开关 INLINE_LABEL=true：文字居中压在水平骨上方（下划线范式）
        产出一：每节点 (行数 hlines, 文本宽 Wtext, 有效字号 f)

Pass 1  族内在需求（自底向上）
        H_k = ((n_k-1)/t_span) · max_j (d_j + u_{j+1} + h_row + δ)      ← 定理 4 反解
        L_k = H_k / sin60；L_k^span = L_k·cos60 + 标题框半宽 + pad
        R_k^span = max_j ( ℓ_j + margin )                                ← INLINE 时不再叠加 Wtext
        产出二：各族 (L_k, R_k, H_k)

Pass 2  半区自治串联（定理 1 + 定理 2）
        上区 top[]、下区 btm[] 各自保序前缀和 → x_k
        W = max(W_top, W_btm)；两半区共享 tail 起点、共同右端接鱼头

Pass 3  剪刀错位（用户 ④）
        下区整体 x += δ，δ = clamp(0.5·min(族宽), 40, ...)，断言不减少净空

Pass 4  缩放闭环（定理 5）
        s = min((W-2p)/Wc, (H-2p)/Hc)
        if f·s < f_min: 收紧 G → 触发 Pass 0 阶梯 → 重跑（≤2 轮）
        否则落盘：fitView(padding = p/scale) 使逻辑坐标与视口 1:1，避免二次缩放
```

### 10.2 三订：回到原始实现的范式（「按需不等高 + 允许族交叉 + 冲突才扩展」）

回溯远端仓库初始提交 `0b524da:components/FishboneDiagram.tsx`（354 行）确认原始三条：

`dynamicLen = 140 + w × 65`（大骨按负载**不等高**）、`branchLen = (50 + w×35) × 0.88^(level-1)`（分支逐级衰减）。

对照本轮两次误改，最终定稿：

| 维度 | 首轮（错） | 二轮（错） | 三轮（定稿） |
|:--|:--|:--|:--|
| 大骨长度 | 按需生长 | **全局等长**（拉出大片空骨） | **按需不等高**（与原始实现同构） |
| 族间关系 | 整族包络互斥（过宽） | 整族包络互斥 | **允许交叉，只保证元素不重叠** |
| 扩展触发 | 预计算包络 | 预计算包络 | **检测到真实相撞才扩展**（元素级） |
| 行分布 | 动态收窄（骨两端空） | 固定 22%–78% | 固定 22%–78%（同原始） |

**元素级冲突驱动的定义**（`utils/fishboneGraph.ts`）：族 $i$ 的位移取

$$x_{i} = \max\Big(x_{i-1}+s_{\min},\ \max_{j<i}\big(x_j + \Delta_{j,i}\big)\Big),\quad
\Delta_{j,i}=\max_{\text{相撞的 } a\in\Omega_j,\, b\in\Omega_i}\big(a.x_2-b.x_1+G\big)$$

约束只在「文本 AABB 的 Y 区间重叠」或「骨段与文本真相交（Liang–Barsky）」时成立，否则 $\Delta=0$ —— 这就是交叉的来源。

## 12. 间隔弹性化（R29 · 六订 / P1 落地）

### 12.1 定义

**只有「间隔」可弹性化，元素尺寸钉死**（字号、文字宽高、分支骨长、标题框一律不动）：

$$\text{gapScale}_{t+1}=\text{gapScale}_t\cdot\operatorname{clamp}(1/\text{deficit},\ 0.65,\ 0.90)$$
$$G_\ell=\operatorname{clamp}(70\cdot\text{gapScale},\ 24,\ 96),\qquad G_r=\operatorname{clamp}(10\cdot\text{gapScale},\ 4,\ 16)$$

替换原来写死的三档（`70/40/24`、`10/6/4`）。每轮最多压 35%，连续逼近。

### 12.2 实测

| 用例 | gapScale 轨迹 | 结果 |
|:--|:--|:--|
| 经典 4 大骨（1200×800） | 1.00（首轮即可读） | fit 78.0%，9.75px，与档位版一致 |
| 长文本 4 大骨 | 1.00 | fit 74.5%，9.32px，一致 |
| 5M1E 6 骨（1200×800） | 1.00 → 0.65 → 0.42 → **0.34（到底）** | fit 48.3%，6.03px + warning |
| 6 层深钻压力用例 | 压到底 | 1 处 57px² 擦边（known-issue 上限内） |

### 12.3 诚实结论：当前用例集下"弹性"与"档位"结果相同

现有 4 个用例要么"首轮即可读"（gapScale=1），要么"压到底"（gapScale=0.34→clamp 到 24/4）。
**没有落在中间态的用例**，所以数值上无差异。

弹性的价值在**中间态**：

| 场景 | 旧（三档） | 新（弹性） |
|:--|:--|:--|
| 轻微不可读（deficit ≈ 1.1） | 直接从 70 压到 40（**−43%**，过度收紧、观感变挤） | 压到 63（**−10%**，刚好够） |
| 中度不可读（deficit ≈ 1.5） | 70 → 40（可能仍不够，再跳 24） | 70 → 47 → 34（两轮平滑到位） |

即：**避免"过压"与"跳档抖动"**，而不是减少总尺寸。整体尺寸的主导项仍是骨长 `dy` 与文字外挂宽度，那要 P3（分支级 t 重排）才有量级收益。

## 13. 尝试「行按需求顺序铺满」：失败与回退（R29 · 七订）

### 13.1 用户观察（正确）

P1 之后「新主骨」族内出现大量空余。实测（你的 6 层用例）：

| 族 | 骨高 H | 行分布跨度 | 占比 |
|:--|:--:|:--:|:--:|
| 人 (Man) | 291 | 134 | **46%** |
| 机 (Machine) | 376 | 173 | **46%** |
| 新主骨 | 647 | 298 | **46%** |

**每个族恰好 46%** —— 因为行分布固定在 `tSpan = [0.28, 0.74]`，两端各留 27% 纯空白。
P1 只弹性化了「gap」，没有弹性化「行在骨上的分布」。

### 13.2 尝试方案（两次）

1. **顺序累加**：`rowPos[j+1] = rowPos[j] + toward_j + rowGap`，`H = inner + Σ + outer` —— 行距 = 各自需求。
2. **富余时弹性铺满**：若 `H > 累加需求`，把行均铺到 `[inner, H−outer]`，消除空白。

### 13.3 为什么失败（根因）

骨高不是静态的 —— **分类修补器会按冲突持续增大 `heightReq`**。于是：

```
修补器扩高 → 铺满把新增高度转成行距 → 行更散 → 触发新的跨族冲突 → 再扩高 → …
```

三处硬伤（均已复现）：

| 现象 | 断言 | 根因 |
|:--|:--|:--|
| 内容不降反升（1331×1053 → 1749×901） | — | 扩高与铺满互相放大 |
| 行距不足 | G3 失败 | 铺满判断用 `height ≥ rawNeed`，但 `max(inner, CLEAR)` 使可用区间变小 |
| 脊椎线穿行文字 | G4b 失败 | 铺满会把行推到 `t≈0.02`，跨过脊椎净空 |

### 13.4 处置：回退，保留结论

已回退到「固定 `[0.28, 0.74]` 区间 + P1 弹性 gap」，`test:fishbone` 45 项恢复全绿。

**根本判断**：行分布与骨高修补是**强耦合**的两件事，必须在同一层求解；在当前「生成器（算需求）→ 消歧器（改高度）」的两段式里局部改，只会把 G3/G4 打穿。

### 13.5 正确路径（顺序不可颠倒）

| 步骤 | 内容 | 为什么必须先做 |
|:--|:--|:--|
| ① | **把骨高从"修补器的可变参数"里拿掉**：消歧器只改 `baseX`（族间）与分支 `length`，不再动 `heightReq` | 去掉耦合，铺满才有稳定输入 |
| ② | 行分布改为「按需求累加 + 富余铺满」（本次原型已验证几何正确） | 消除 46% 空白 |
| ③ | 若仍冲突，用**分支级 `t` 重排**而非扩族高 | 从根上解决链内重叠 |

即：**先解除耦合，再改分配**。这也正是用户提的「生成器 / 消歧器解耦」架构。

### 13.6 诚实结论

- 本轮**没有达成**「消除族内空白」的目标，代码已回退，无回归；
- 但把失败根因定位到「骨高被修补器动态修改」这一具体耦合点，并给出 ①→②→③ 的可执行顺序；
- 现有交付状态：`test:fishbone` 45 项全绿、6 骨用例 0 重叠 0 穿刺、4 骨用例 8.62px 可读。

## 16. 分支级 t 重排：收益落地，但被「bbox 口径」卡住（R29 · 十订）

### 16.1 做了什么

把「按需求分配」从**族的行**推广到**每一层的兄弟分支**：

$$t_j = t_{\min}+\frac{\sum_{k<j}\text{arc}_k+\tfrac12\text{arc}_j}{\sum_k \text{arc}_k}\cdot(t_{\max}-t_{\min}),
\qquad \text{arc}_j=\begin{cases}W_{\text{text},j}/2+G,&\text{父骨水平}\\h_j+G,&\text{父骨 }60°\end{cases}$$

父骨长度同步改为 $L=\sum_j \text{arc}_j/\text{span}$（按需求之和，不再按"最大值×n"）。

**一处关键修正**：`arc` 只能是「子项在父骨方向占用的**文字跨度**」，不能含 `length·cosα`
（子项沿垂直方向伸出，不占父骨弧长）。误加后父骨被拉长近 2 倍、宽度 +38%。

### 16.2 收益（实测）

| 用例 | 改前 | 改后 |
|:--|:--|:--|
| 4 骨 3 层 @1600×1000 | fit 98%，9.79px | **fit 100%，10.00px** |
| 6 骨 4 层 @1920×1200 | fit 99%，9.89px | **fit 100%，10.00px** |
| 4 骨 3 层 @1200×800 | 7.18px | 7.26px |

即：**升档后可读性从"勉强"变成"满格"**，与「不肥」的观感目标一致。

### 16.3 但引入 1 处链内擦边，已回退

`edge-anchor-m2`（大骨斜线）与「冷却水流量不足」（同族深层文字）出现 10px 级擦边，
`resolveLabel` 的「撞斜骨 → 退化外挂」本应拦截却没有 —— 因为 **`labelBoxOf`（布局内）与
`textBoxes`（断言内）对 60° 骨的 `labelDy` 解释不一致**。

同一个口径问题，正是 §15 里「纵向文字下半区不居中」的根因。

### 16.4 结论：下一步只有一件事 —— 统一 bbox 口径

| 现状 | 后果 |
|:--|:--|
| `labelBoxOf` / `textBoxes` / G6 渲染 三处对 `top`/`bottom`/`center` + `labelDy` 的解释不完全一致 | ① 布局的"撞斜骨退化"判定漏判；② 纵向文字下半区观感偏移；③ 分支级重排无法闭环 |

**正确次序**：
1. **定义唯一的文字盒函数**（`labelBoxOf` 为 SSOT），断言与布局都调它，G6 的 `placement` 只作为"渲染提示"；
2. 用 `center + labelDy` 做上下对称偏移（不依赖 G6 `top`/`bottom` 语义）；
3. 重跑分支级 t 重排 → 擦边自动消失，同时「下半区文字居中」一并修好。

代码已回退（`BEFORE_T` 备份在 `/tmp`），当前 65 项断言全绿、无回归。

## 17. 「重复计算」定位与修复：骨高虚高 60%（R29 · 十一订）

### 17.1 重复 #1：端点约束 vs 铺满归一化

旧 `heightReq` 同时叠加了：

$$H=\max\Big(\underbrace{\tfrac{n-1}{t_{\text{span}}}S}_{(a)\ \text{行距反解}},\ \underbrace{\tfrac{d_{\text{inner}}+G}{t_{\min}}}_{(b)\ \text{端点}},\ \underbrace{\tfrac{u_{\text{outer}}+26}{1-t_{\max}}}_{(c)\ \text{骨端}},\ 180\Big)$$

而 materialize 的行位已改为「按需求累加 + 线性铺满 `[inner, H−outer]`」——**（b）（c）两种不越界已由铺满保证**，
再叠加就是把骨高顶大：实测「人」族 $H=291$，而真实累加需求只有 $\sim163$，**冗余 60%+**。

修复：$H=\max\big(\text{rawNeed},\ 180\big)$，`rawNeed = d_inner + u_outer + 2G + Σ(相向需求 + 行高 + G)`。

### 17.2 重复 #2：修补器扩高无上界

`resolveConflicts` 的 sibling/intra 会 `heightReq += need`，但对「链内相对位置固定」的冲突扩高**根本不解决**，
只是逐轮累加 → 全变成空白。修：加 `cap = 1.35 × rawNeed`，超界改走族间推移。

### 17.3 实测（4 大骨经典用例）

| fitScale / 最小字号 | 78.0% / 7.94px（不可读） | **85.6% / 8.56px（可读）** |
| 收紧轮次 | 5 轮 | **1 轮** |

6 骨用例同样从 1986×1160 → **1859×642**（高 −45%）。

### 17.4 仍未解决

- 行分布虽已铺满（46% → 68–84%），但**行距仍由 `heightReq` 与 `towards` 的比例决定**，不是严格的"每行各自需求"；

## 20. 真凶：G6 v5 的标签偏移字段是 `labelOffsetX/Y`，不是 `labelDx/Dy`（R29 · 十四订）

### 20.1 症状

「下半区纵向文字不居中」反复修不好；改成 `center + dy ±(h/2+6)` 后用户反馈"**没变化**"。

### 20.2 根因（读源码确认）

`node_modules/@antv/g6/lib/elements/nodes/base-node.js`：

```js
getLabelStyle(attributes) {
  const { placement, maxWidth, offsetX, offsetY } =
    subStyleProps(this.getGraphicStyle(attributes), 'label');
  ...
  return Object.assign(getTextStyleByPlacement(keyBounds, placement, offsetX, offsetY), ...);
}
```

`subStyleProps(style, 'label')` 取的是 **`labelOffsetX` / `labelOffsetY`**。
而鱼骨图一直在写 **`labelDx` / `labelDy`（G6 v4 的字段）** —— v5 **完全不识别**。

> 所以从第一版起，**所有标签偏移都没生效过**：
> · 60° 骨的文字永远"居中于端点"、无内外侧位移 → 上下半区看起来都不对（尤其下半区与刺尖重叠）
> · 水平骨文字的 6px 间隙也从未生效（紧贴端点）

这解释了为什么"改了几轮都没变化"：改的是**没人读的字段**。

### 20.3 修复

1. emit 时**同时**写 `labelOffsetX/labelOffsetY`（G6 v5 生效）与 `labelDx/labelDy`（旧版/探针兼容）；
2. `textBoxOfNode`（SSOT）优先读 `labelOffsetX/Y`、回退 `labelDx/Dy` —— 保证布局判定与真实渲染同口径。

### 20.4 为什么我的出图"看不出变化"

离线探针（`/tmp/fb-svg.ts`）自己读 `labelDx/Dy` 渲染，所以**它一直显示的是"数学定义上的位置"，而不是 G6 的实际渲染**。
这也说明：凡是"探针正确、页面不对"的差异，优先怀疑**组件/渲染层的字段或语义**，不是布局数学。

### 20.5 门禁

`test:fishbone` 66 项全绿（bbox 走 SSOT，字段切换不改变几何定义）。
后续若再加标签特性（换行、行高、最大宽度），一律先查 G6 v5 的 `subStyleProps(style,'label')` 支持哪些键。

## 21. 横向按需求：span 判断取反的 bug（R29 · 十五订）

### 21.1 症状

「调机参数设置不当」这条中骨很长，4 个子项却挤在左半段，右半段空白 —— 用户判断"不是按需定的"，正确。

### 21.2 根因：区间判断取反

深层子项沿父骨的占用区间按"父骨类型"分了两档：

| 子项类型 | 末端是否要留文字区 | 应取区间 |
|:--|:--:|:--:|
| **60° 骨**（文字居中于端点，不占骨内） | 不需要 | **0.12–0.88** |
| 水平骨（文字在端点**外挂**） | 需要 | 0.20–0.62 |

但代码里写成了 `span = parentHorizontal ? H : V` —— 用**父骨**类型去选，恰好取反：
中骨的子项是 60° 骨、本可铺满，却拿了 0.42 的保守区间 → 骨长按 `/0.42` 反解被放大 1.8 倍，
子项仍只占 42% → **右半段空白**。

修正：改用**子项**类型判断（`childHorizontal = (level+1) % 2 === 0`）。

### 21.3 实测（用户用例）

| 指标 | 修复前 | 修复后 |
|:--|:--:|:--:|
| 中骨长度 | 237px | **158px** |
| 子项锚点间距 | ~180px | **~75px** |
| 内容包围盒 | 1368×390 | **1129×402**（宽 −17%） |

## 22. 同层级两种排列的根因：退化分支改了方向（R29 · 十六订）

### 22.1 症状（用户指出）

同一层级（都是小骨）的纵向标签，有的**居中于刺尖**、有的**居右**，排列不统一。

### 22.2 根因

`resolveLabel` 在「文字撞到斜骨」时**退化为水平外挂**（文字移到端点右侧/左侧）。于是：

| 情形 | 结果 |
|:--|:--|
| 未撞斜骨（多半在上半区） | `center` + `labelDy` ⇒ **居中于刺尖** ✓ |
| 撞斜骨（多半在下半区，靠近脊椎侧） | 退化 ⇒ **居右** ✗ |

两种排列并存 = 用户看到的"同层级两种排列"。

### 22.3 修复：退化不再改方向，只沿骨刺外移

$$	ext{碰撞时：}\ dy \leftarrow \pm\Big(	frac h2+6+k\cdot(	frac h2+4)\Big),\ k=0,1,\dots$$

即保持「水平居中于端点」，只在垂直方向**逐次外移**直到不再撞斜骨。
这样同层级的排列语义唯一：**永远居中于刺尖外侧**。极端情况（外移 8 次仍撞）才退化为外挂。

### 22.4 副作用澄清：**不需要改独立 text 节点**

上半区标签能正确偏移，说明 G6 v5 的 `labelOffsetY` 在 `center` 下**是生效的**；
之前"下半区不居中"完全是**退化分支改了方向**造成的，不是渲染层。

> 因此 §21 末尾设想的「标签改独立 text 节点」**取消**：现有 `center + labelOffsetY` 方案已足够，
> 避免了一次不必要的大改（那次改造会引出跨族 seg×text 擦边，已回退）。

### 22.5 状态

`test:fishbone` 66 项全绿；`validate:dsl` ×3；`test:flow` 15 pass。

## 23. 标签改独立 text 节点 + 间距统一 8px（R29 · 十七订）

### 23.1 为什么之前"没变化"

上一轮把「退化」从改方向改成「沿骨刺外移」，但用户反馈**居中没有变化** —— 说明 `labelOffsetY` 压根没生效。
实测：`center + labelOffsetY=+13.5` 的下半区标签仍贴着端点。**G6 v5 的 label offset 在 `center` 下不生效**。

### 23.2 定稿方案：标签独立成 `text` 节点

```ts
// 分支端点只保留无标签的 circle
{ type: 'circle', style: { x: end.x, y: end.y, size: … } }
// 标签是独立节点，坐标由布局精确给出
{ type: 'text', style: { x: lbl.cx, y: lbl.cy, text, fontSize, textAlign: 'center', textBaseline: 'middle' } }
```

从此**文字坐标由布局唯一决定**，不依赖 G6 的 placement/offset 语义 —— 彻底消除"渲染层与布局层口径不一致"这一类问题。

### 23.3 间距统一

新增 `T.labelGap = 8`，**横向与纵向共用同一个常量**：

| 方向 | 规则 |
|:--|:--|
| 水平骨 | 文字块边缘距端点 **8px**（整块在端点外） |
| 60° 骨 | 文字**水平居中于端点**，垂直边缘距端点 **8px**（随骨刺方向，上下对称） |
| 撞斜骨 | 沿同一方向继续外移（每次 +h/2+8），保持"居中于刺尖"语义，**不改方向** |

### 23.4 效果

| 指标 | 之前 | 现在 |
|:--|:--:|:--:|
| 纵向标签位置 | 恒贴端点（下半区压骨） | **刺尖外 8px，上下对称** |
| 同层级排列 | 居中 / 居右 两种 | **统一为居中** |
| 4 骨 @1200×800 | 90.2%，9.02px | **91.5%，9.15px** |
| 长文本 @1200×800 | 87.2%，9.16px | **89.3%，9.38px** |

### 23.5 连带修正

- `minFontSize` 统计需包含 text 节点的 `fontSize`（否则会误取 16px，可读性判定虚高）；
- 断言「分形保真」改为按**分支端点节点**判断（`circle` 且非 `ba-`/`anchor-`），因为标签已不在 circle 上；
- 离线探针需渲染 `type: 'text'`，且不再回退读 `data.label`（否则标签渲染两次）。

### 23.6 状态
