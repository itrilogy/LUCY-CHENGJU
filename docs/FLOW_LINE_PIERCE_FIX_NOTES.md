## 2. 根因定位（探针逐边诊断）

用真实样例（`INITIAL_FLOW_DSL`）探针逐条打印所有 9 条边的 `path`，结合 `computeExcelLayout` 节点坐标，确定两份贯穿分别来自两条同列相邻边的**错误绕路**：

### ① 边 `w1→w2`（开始→填写申请单，同列相邻）

```
修复前: M170,173.9 L170,74 L170,217.7
```

- w1 中心 `(170,134.9)` 44×44，w2 中心 `(170,256.7)` 120×44。两者**同列(c0)**，w1 在 w2 正上方，本应一条**竖直短直线**。
- 实际路径：源端口 B `(170,173.9)` → **上折到 `(170,74)`** → 再 `(170,217.7)` 落到 w2 顶部端口。
- `(170,74)` 是**上一行网格边界**。竖线 `(170,74)→(170,217.7)` 正好穿过 w1 盒（y:114.9~154.9）中间。

### ② 边 `w4→q2`（经理审批→审批是否通过，同列相邻）

```
修复前: M365,417.5 L365,317.6 L365,456.4
```

- w4 中心 `(365,378.5)` 120×44，q2 中心 `(365,500.3)`。同列(c1)，w4 在 q2 正上方。
- 同样被吸附到上一行边界 `y=317.6`，上折后穿回 w4 盒。

### 根因一句话

`buildRoute` 只处理了两点重合（`s==t`），**漏了同竖直轴 / 同水平轴相邻节点的直连特判**。当源端口 **B** 与目标端口 **T** 同列（`s.x === t.x`）时，程序误入 `竖-横-竖` 分支：
- 该分支用 `snapTo((s.y+t.y)/2, yMarks)` 把横段吸附到行网格线；
- 对同列相邻节点，这是**画蛇添足**——吸附把 y 推到了错误的上一行边界，形成"上折 → 回穿源节点"的绕路。

**为何此前 ALIGN-8 撤回**：它试图通过调整端口分配来规避贯穿，但真正的根因在 `buildRoute` 对"同轴相邻节点"应走直线却走了带 snap 的分支——换端口治标不治本。

## 3. 修复做法

在 `buildRoute` 顶部、点重合判断之后，新增两档**同轴直连特判**：

```ts
if (Math.abs(s.x - t.x) < 1 && Math.abs(s.y - t.y) < 1) {
  pts = [{ x: s.x, y: s.y }, { x: t.x, y: t.y }];
} else if (Math.abs(s.x - t.x) < 1) {
  // 同竖直轴：源 B / 目标 T 同列相邻，直接竖直连接，不插横段、不 snap
  pts = [{ x: s.x, y: s.y }, { x: t.x, y: t.y }];
} else if (Math.abs(s.y - t.y) < 1) {
  // 同水平轴：源 R / 目标 L 同行相邻，直接水平连接
  pts = [{ x: s.x, y: s.y }, { x: t.x, y: t.y }];
} else if (horiz1 && horiz2) {
  ...
}
```

原理：同列/同行的相邻节点，两端口本就在同一根轴线上，**直连即最简路径**；`snapTo` 的吸附只应用于真正**跨行/跨列**的边，避免把 y/x 吸到错误边界。这样既修掉贯穿，又不破坏 ALIGN-5"拐点吸到行列边界"的网格对齐（该特性对跨行跨列边保留）。
