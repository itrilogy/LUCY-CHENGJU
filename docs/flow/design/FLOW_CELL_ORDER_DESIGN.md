## 1. 核心问题 1：vh 缺省 = 全纵向，需核查扩展格算法

用户提示："VH 如果写者的定义丢失，极容易发生泳道格内节点一致保持纵向或横向排列。"

### 根因诊断（已核实）

- `FlowParser.ts` L567-576：`vh` 从节点行尾解析，**未标注 → `undefined`**。
- `flowToSVG.ts` L534：`const dir = n.vh ?? 'V'` —— **未标注一律当 V（纵向）**。
- 故：同格多节点若全未写 vh（或漏写），**全部按 V 纵向堆叠**，即便意图是横向/对角。

**本质**：算法不"丢" vh，而是**缺省默认一刀切 V**。这正是"格内一致纵向"的根因。

### 扩展格算法核查结论

- 扩展格（③）本身正确：`nx/ny = max(gridX/gridY + 1)`，`colWPx/rowHPx` 按 `nx_max/ny_max` 整行/整列统一扩展，与 vh 方向无关——**扩展格算法无缺陷**。
- 问题纯在 b 阶段排序键：**缺省默认 V** 决定格内走向，缺省不明智则走向单一。
- **修正方向**：b 阶段排序后，**缺省 vh 按"格内拓扑序的上游方位"智能推导**（相对新上一节点：y 大→V、x 大→H、双大→D），使未标注节点沿流向自然排布，而非一刀切 V。

## 2. 设计：格内拓扑序 + vh 保持/智能缺省（b 阶段升级）

用户已确认排序键 = **格内拓扑序**。

### 排序键

- **输入**：同一交叉格 `(ri,ci)` 内的 items（节点集合）+ 顶层边（`data.edges`，过滤 parent）。
- **规则**：按格内节点间 `from→to` 直接边做**拓扑排序**，使流向相邻节点在格内也相邻（上→下、左→右朝向一致）；**无直接边（孤立/仅外部边）按声明序兜底**。
- **确定性**：Kahn 拓扑序 + 稳定归并（多入度起点按声明序齐位），无随机。

### vh 处理（与用户定义一致）

- **显式 vh 保持**：作者标注的 `V/H/D` **值不变**，只是"相对谁"随重排后的新上一节点变化（保留用户语义）。
- **缺省 vh 智能推导**：未标注节点按其在新拓扑序中的相对上游方位推 `vh`（y 大→V、x 大→H、双大→D）；若为格内首节点无参照 → 默认 V。
- **规避冲突**（本轮探测已实测）：不"覆盖重算 vh"，只"保持 + 缺省推导"——避免破坏作者显式语义。

### 首节点锚定

- 拓扑序**首节点**恒 `(0,0)`（沿用 L529-531 规则）；重排改变"谁在原点"，连带影响 N/DATA 对齐（`item.gridY`）与松弛引擎探测——**属接收的连锁，需回归断言锁定**。
