## 2. 修正原则

1. **网格是唯一骨架**：行=泳道（或单维最大链长），列同理；内部节点、标注、数据对象不得增行增列。
2. **整行整列统一扩展不放松**：格内 V/H 链仍然撑开该行/列，其它交叉格等分对齐。
3. **节点仍居中于绘制格**；修饰类依附前驱，画在走廊，不占用新交叉格。
4. **折行按字宽、不拆数字**；文字能装进图元则不加底板。
5. **连线拐点优先吸到行列边界（格子通道）**；同行走横、同列走竖。

## 3. 修正过程（随实现追加）

> 以下各小节在代码落地后立即回填验证结果。

### 3.1 ALIGN-1 单维轴按「各泳道最大节点数」扩格

**根因**: `cols = Array.from({ length: nodeCount })`（H 单维）/ `rows = Array.from({ length: nodeCount })`（V 单维）。3 个节点跨 2 条泳道也会生出 3 列。

**做法**: 先按泳道列表归类，再令虚拟轴长度 = `max(各泳道序号)+1`，不再用 `data.nodes.length`。

**验证**: 探针 `cols len 3 → 2`；`w1 ci:0 / w2 ci:0 / w3 ci:1`；断言「单维列数=最大链长(2) 而非节点数(3)」通过。`rowHpx [112, 112]` 两泳道等高，整齐对齐保持。

### 3.2 ALIGN-2 子流程内部节点退出主网格

**根因**: `parent` 节点 `cell=null` 走自动落格，在单维里继续占 `ri=3..6`。

**做法**: `isLayoutNode` = 无 `parent` 且非 annotation/dataObject。内部节点不进 `group`/`nodePos`（本轮不画内嵌小图，子流程节点画 BPMN「＋」盒表示可展开）。

**验证**: 探针 `layout pos` 仅 w1/q1/w2/q2/w3，无 s1..s4；`maxRi=2`（3 条纵向泳道内的链长），不再出现 ri=3..6。子流程节点绘 10×10 展开＋盒。

### 3.3 ALIGN-3 标注/数据对象不占格

**根因**: N/DATA 与活动节点一起参与 `laneSeq`。

**做法**: 从主网格分类排除；布局完成后依附声明序前驱，落在前驱右上走廊；若超出画布则只撑 `width/height`，**不改** `gridRight/gridBottom`（泳道线仍对齐网格）。

**验证**: 探针 `N/DATA in layout [{n1, ri:0, ci:3}, {d1, ri:0, ci:3}]` —— 与前驱并行网关同格走廊，不新增列。主网格列数仍由活动节点链长决定。

### 3.4 ALIGN-4 按字宽折行、数字不拆、取消无谓底板

**根因**: `wrapLabel(..., 6)` 按字符数切；`nodeMetrics` 按整串宽度撑菱形，渲染又强制 6 字折行，再盖 `#475569` 底板。

**做法**: `wrapLabel(text, maxWidth, fs)` 按 `textW` 贪心；`[0-9.]+` 视为原子；任务/网关按图元内宽折行；仅当行宽仍超出内宽才加底板。

**验证**: 「金额超过5000?」不再切成「50/00?」；开始节点「提交采购申请」保持整句（圆上底板承载）。断言「折行不切断数字 5000」通过。

### 3.5 ALIGN-5 连线走格子通道

**根因**: 拐点取 `(s+t)/2` 几何中点；同行/同列未强制 R-L / B-T。

**做法**: 同行优先左右端口、同列优先上下端口；U 型中段 `snap` 到 `colX` / `bandTop` 网格线；L 型穿节点时改走边界 Z 通道。

**验证**: 既有正交折线断言仍 4+ 条；同行/同列端口优先 + 拐点 snap 到 `colX`/`bandTop`；穿节点时改 Z 通道。未改 3×3 绘制格与整行整列扩展。

### 3.6 ALIGN-6 / ALIGN-7 图面规整

- 属性图例与节点右下角岗位：字典引用展开为字面量。
- 并行网关菱形内画「＋」；`e.default` 在首段近源处画斜杠。

**验证**: 探针 `hasApplicant true`（不再出现 `R[0]`）；`has plus for parallel true`；`default-flow slash true`；断言「岗位字典展开为 申请员」通过。
