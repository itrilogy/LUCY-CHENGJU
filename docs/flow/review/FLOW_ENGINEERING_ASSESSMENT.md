## 9. 回归设计中心思想：精炼数据方法「1 盒子 · 居中 · 贴边 · 同款格数学」（2026-08-31）

### 9.1 根因再确认（回应"为何出大问题"）
此前几轮修订在实现细节上**偏离了 `FLOW_LAYOUT_ENGINE_DESIGN.md` 的中心思想**，把简单规则做乱了：
- ④"subprocess=140×48 基础尺寸" → 我武断改成"按内部节点数放大到 176×90 并推动泳道"。
- ⑤⑥"**箭头抵目标节点边中点，不超出**" → 端点落在"走廊中线"（距边 half/2=17px），箭头没抵到节点边 → 你看到的"不指向入口/指向格子"。
- ③"单节点格 1 格居中、空列用基础格" → 复杂示例塞节点挤格。

### 9.2 精炼数据方法（回到中心思想）
**「1 盒子 · 居中 · 贴边 · 同款格数学」** 四规则：
1. **一切皆格子**：主流程 = 泳道交叉格矩阵；子流程 = 一个普通格子节点，内部再套一层同款矩阵（等比缩小）；连线走格子间走廊。
2. **行列宽度统一**：列宽=该列最大 nx×(节点最大宽+2half) 整行统一；行高同理；空列/空行=基础格。
3. **节点一律居中、不超格**：节点中心=绘制格中点；节点宽=自身文字自适应（≤该列已算好上限）。
4. **连线端点一律贴上节点边中点**：端点=节点边界（`W/2`,`H/2`），不加走廊偏移，箭头尖指入口。

### 9.2.1 子流程 = 标准泳道交叉格整数倍（用户确立）
子流程严格是"标准泳道交叉格的**整数倍**"：`宽=k×subprocess.w、高=mm×subprocess.h`（k/mm 由内部节点数、内部按同款格子数学排布），从而与相邻泳道/交叉格**无缝对齐、不超格、整数格推动泳道**。

### 9.3 落地（回归中心思想）
- `flowToSVG.ts`：
  - `portXY` 端点=节点边界（去 half/2 走廊偏移）→ 箭头抵节点边中点（⑤⑥）。
  - 子流程尺寸改 **k×140 / mm×48**整数倍（替换此前武断 needW/needH），内部小图列数=√N（同款格子）。
- 实测：子流程 w10 `280=2×140`、`96=2×48`（整数倍）；连线端点距节点边**最大 0.00px、0/23 距边>0.6px**（全部贴边=指向入口）。

### 9.4 回归
`npm run test:flow` **131 项全绿**；`npx tsc --noEmit` 零错。
