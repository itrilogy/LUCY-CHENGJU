## 0b. 连线 = 运输调运模型（2026-08-31 闭环落地：全局 WSAD 硬性互斥与几何中点对齐）

用户把连线路径问题规范为**运输/调运问题**，作为连线算法的**权威总纲**：

1. **建立调运路线**：根据源（OUT）与目标（IN）先建初始调运路线——严格正交折线（曼哈顿，绝无曲线与斜线）。
2. **一个方向要么全出，要么全入（WSAD 严格单属性互斥）**：
   - 每个节点的四个侧边 $d \in \{T, B, L, R\}$，在全局生命周期中只能是 $\text{UNUSED}$、$\text{INPUT}$、$\text{OUTPUT}$ 之一；
   - 硬性约束：$\operatorname{UsedInDirs}(u) \cap \operatorname{UsedOutDirs}(u) = \emptyset$，**绝对禁止同一边既出又入**；
   - 算法采用全局协同两阶段分配：阶段 1 结合目标象限与“出门不撞墙”确定出端口，阶段 2 严格过滤掉所有已占出端口，分配面向源的入端口（允许多入边共用同一纯入端口）。
3. **几何与代数边中点对齐原则（Midpoint Invariant）**：
   - 连线与节点的物理接触点**严格对准节点该边的几何中心点（Midpoint）**（$0.00\text{px}$ 贴边，严禁人工偏移偏移量）；
   - 首段沿边法向垂直引出到连线区中线，末段沿法向垂直射入目标边中点。
4. **城门口接待员【箭头】**：在城门（IN 端口）由独立渲染层绘制唯一的等腰三角形箭头（尖端 $0.00\text{px}$ 贴合目标边中点，OUT 端口无箭头短线）。
5. **局部走廊搜索（彻底消除长纵线贯穿）**：
   - 路径搜索被严格约束在源宿节点局部包围盒 $[\min - 2\text{half}, \max + 2\text{half}]$ 的网格通道中，杜绝无谓贯穿整图的恶性绕行；
   - 仅跨 2 列及以上的大逆向回边才启用顶/底外侧走廊。

**实测结果（2026-08-31）**：
- 全图冲突节点数 = 0；
- 全量自动化测试 131 项断言全部通过，`tsc` 零错误，打包构建成功。

## 0. 一句话回顾（压缩后先读）

IQS-Flow 是「数据层 Dict + 结构层 Lane/节点 + 自研 SVG 渲染」的企业体系文件流程图。核心算法：**泳道交叉格矩阵（X×Y）→ 整行/整列统一扩展 → 节点居中 → 连线走格子走廊（正交曼哈顿）→ 箭头由 IN 属性独立渲染**。近期用户围绕「节点落地/泳道对齐/连线路径复用/箭头指向」提出多轮修正。

## 1. 布局（computeExcelLayout）

### 1.1 核心（设计③④）
- 行列：`rowsOf/colsOf`（Lane from 的 H/V）；无泳道 → ROOT 占位。
- **整行/整列统一扩展**：
  - `列宽 = 该列最大 nx × (该列节点最大宽 + 2×half)`，该列所有交叉格按 nx_max 等分。
  - `行高 = 该行最大 ny × (该行节点最大高 + 2×half)`。
  - 空列/空行用基础格 `BASE_W=100 / BASE_H=60`。
- **节点严格居中**于绘制格（`cx = colX[ci] + gridX*pw + pw/2`）。
- 子流程 = **标准泳道交叉格整数倍**：`宽=k×subprocess.w、高=mm×subprocess.h`（k/mm 由内部节点数、内部同款格子数学），与相邻泳道无缝对齐、不超格。
- `NODE_BASE`：task 120×44、subprocess 140×48、gateway 80×50、start/end 圆 r=22、annotation 120×36、data 100×36；文字自适应不低于基础。

### 1.2 N/DATA（DOC 虚拟泳道）——已落地
- 出现顶层 annotation/dataObject 时，`cols` 最右侧追加 `DOC` 列（文档信息泳道）。
- N/DATA 落格到 `(依附行, DOC列)`，依附行 = attach 目标主网格行（`attachRowOf`）——与依附节点**横向对齐（对齐优先）**。
- 同依附多 N/DATA 纵向避让（推动行高）；已撤销旧"依附前驱右侧漂移"。
- N/DATA→依附 用**虚线**（`condition:'__doc__'`，dasharray），走同一连线逻辑。

### 1.3 已知问题（扩展格 vs 连线耦合）
- **连线不驱动扩展格**：连线穿越格子靠**避障绕行**，格子不会为走廊让位/扩列扩行。→ 长回边会绕到画布边缘（"连线引起布局扩展"属前提3，未耦合）。
- 子流程内部节点不占主网格（`isLayoutNode` 排除 parent/annotation/dataObject）。

## 2. 连线（flowToSVG 连线段）

### 2.1 端口（WSAD，设计⑤）
- 4 端口 `T/B/L/R`（上/下/左/右），`portXY` 端点 = **走廊中线**（`±W/2 ± half/2`，`half=L.half/2`）。
- **两趟分配**：第一趟入口 `targetCandidates(b,a)` → `usedIn`；第二趟出口 `sourceCandidates(a,b)` → `usedOut`。
- **WSAD 单属性（设计⑤"出入口不共用同一侧"）**：出口选择避开 `usedIn∪usedOut`（同侧不既入又出）。`targetCandidates` 面向源一侧（同列 b 在下→b 顶入等）。

### 2.2 路径（buildRoute）
- 正交曼哈顿：同轴直连 / L型一次拐弯 / U型 / Z型（`horiz1∧horiz2`→横竖横，`!horiz1∧!horiz2`→竖横竖，否则 L 型）。
- 中段吸附行列边界（`snapTo(mid, xMarks/yMarks)`）。
- **去零长段 + 共线合并**（仅单路径内，L942-949）。
- 确定性避障：`routeHits`（Liang-Barsky 段×节点盒）+ `tryOrder`（螺旋分数 `FRACS=[0.5,1.5,-0.5,...]` × `dw=half`）+ MAX_ROUND=3。
- **clamp（近期修复）**：避障候选走廊 `cx∈[x0, gridRight-half]`、`cy∈[titleH, gridBottom-half]`——不侵入左表头/越右缘。
- 外侧走廊 P3：`corridorX=max(x0-half, bandLeft)` 等，MAX_ROUND 全占后回退。

### 2.3 已知问题（路径复用）
- **未跨边复用**：多条边方向一致时应共用同一条走廊线段/端口短直线，当前未做（仅单路径内共线合并）。
- **长横线绕 Y 轴（已确诊 2026-08-31 深挖）**：
  - **bandLeft=76**（非110），连线纵段走 `x=76` 即贴左表头/穿 Y 轴标题区——`clamp` 用 `x0=bandLeft+titleBandW=76`，**下限正好是76，未能防止"贴左表头走长纵段"**。
  - 症结边：`初审是否通过?→技术评审`（`M365,178 L76,178 L76,461`）、`技术评审退回→商务谈判`（`76~365`）、`商务谈判→商务条件达成?`（`76~567`）——从源**横穿整个画布到最左 x=76** 再竖下。
  - **根因**：`sourceCandidates` 对某些对角/跨行边选了**背向/侧向源端口**（源朝左出），初次 `buildRoute` 便往左绕，避障/吸附兜到最左 `x=bandLeft`；`targetCandidates` 未完全纠正。
  - **修复方向**：源端口强制朝向目标（补 sourceCandidates 对角/跨行时"朝向优先、禁背向"），并让连线走**就近格子走廊**而非统一推左；`x0` 下限应再 +half 以真正避开左表头。
  - **已实施（2026-08-31 深挖）**：
    - `buildRoute` 初次路径统一 **clamp 到网格内**（`x∈[x0+half, gridRight-half]`、`y∈[titleH+half, gridBottom-half]`）。
    - 避障 `tryOrder` clamp 下限改 `x0+half`（避开贴左表头）。
    - P3 外侧走廊左缘 `corridorX = max(x0+half, bandLeft+half)`（不再贴 Y 轴标题带）。
    - 效果：`技术评审退回→商务谈判`（x=76→365 直连）、`商务谈判→商务条件达成?`（x=76→442 就近）**不再穿 Y 轴**；但跨格长边（`初审→技术评审`）因缺"就近走廊"仍兜到右走廊（gridRight+half 横穿）。**根治需"连线驱动扩展格让位"**。
  - **仍未根治**：跨格长边无就近走廊→被迫走外侧（左/右走廊）——"连线驱动扩展格"（前提3大项）未实现。

## 3. 箭头（独立渲染层，已落地）

- **先划线，再按 IN 属性渲染箭头**（`arrowParts` polyline 三角形）。
- 箭头 = 连线区一条"短直线+箭头头"：尖端抵节点边（入口），梯形翅膀在走廊中线（连线端点）。
- **IN 有箭头、OUT 无箭头**（用户设定），每个 IN 端口必有一个箭头（不缺失/不少画）。
- 边 path 已**去掉 `marker-end`**（改用独立箭头层）；`arrowMarker` 定义保留但不再用于边。
- 已知：OUT 端口的"无箭头短直线段"尚未单独绘制（IN/OUT 对称的接头线段待补全）。
