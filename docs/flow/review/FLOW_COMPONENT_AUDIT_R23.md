## 1. 算法文档演进（评估要件从哪来）

只列对「出入口」和「子流程」有约束力的条款。时效以 `docs/flow/README.md` 为准；冲突时按 `protocol/governance.md`：实现以 L0/公理为准，过程记录不覆盖公理。

### 1.1 连线 / 端口（红线的书面史）

| 时序 | 文档 | 条款 | 对「复用」的态度 |
|:--|:--|:--|:--|
| 基线 63566cf | `FLOW_NDATA_LANE_DESIGN.md` §1 | 两趟分配；出口避开入口；`pickPort` 全占则复用首位 | **同向可复用**；出入口互斥 |
| 布局 v6 | `FLOW_LAYOUT_ENGINE_DESIGN.md` §⑤ | 「**出入口可各自共用，但出入口之间不共用同一侧**」 | **正是本次红线的原文** |
| 防失忆 | `FLOW_ROUTING_ALGO_STATE.md` §0b（🔴 描述旧引擎，但 A1 表述仍对） | 「一个方向要么全出、要么全入」；`UsedIn ∩ UsedOut = ∅` **绝对禁止同一边既出又入**；允许多入边共用同一纯入端口 | 红线硬约束 + 同向复用 |
| 需求 M4 | `FLOW_CONNECTION_REQUIREMENTS_ALGO.md` | WSAD 单属性；两趟（先入后出）；同侧不既入又出 | 红线；两趟**实现仍是一趟**（AUD-061，未闭环） |

| 蓝图 | `FLOW_ROUTING_ENGINE_DESIGN.md` §1.2 / §5.1 | `in ∩ out = ∅`，**且**每个端口至多一条边（**除非**汇聚/发散允许复用）。§5.1 默认允许 white-list | 「除非」只放松「一条边一端口」，**不放松 A1** |
| R22 | `FLOW_COMPONENT_AUDIT_R22.md` §2.4 / §9 | `relaxNodes` = 网关白名单，入/出可复用同侧；G5 校验时跳过网关 | **把「除非」安到了 A1 上** —— 本轮要推翻的误读 |

**评估要件（本次判定用，不自造新标准）**：

1. **A1 红线**：任意节点（含网关）`in(n) ∩ out(n) = ∅`。违反 ⇒ 流程图方向语义崩溃（本次截图）。
2. **A3 同向复用**：同一侧多条入边、或同一侧多条出边，**合法**。视觉上可再做槽位错位（评估文档 M1 `0.25/0.5/0.75`，未实现，属增强不是红线）。
3. **朝向是软约束**：背向罚 1000（AUD-143）可以降级；**不能用放松 A1 来换 0 折弯**。
4. **代价优先级**：A1 硬约束 ≫ 背向软罚 ≫ 折弯/长度。R22 对网关做成了「折弯 ≫ A1」。

### 1.2 子流程（同一套范式从哪来）

| 文档 | 承诺 |
|:--|:--|
| `FLOW_ROUTING_ENGINE_DESIGN.md` 前提② | 子流程是**等比例缩放的流程节点**，影响泳道/交叉格高宽 |
| `FLOW_NDATA_LANE_DESIGN.md` §二 / §四 | 整数倍标准格（140×48），与 ③ 整行整列统一扩展对齐 |
| `FLOW_LAYOUT_ENGINE_DESIGN.md` ①②③④ | 外层范式 = **3×3 绘制格**（中心放节点、四周 `half` 走廊、端点在边中点、首末段法向）+ 交叉格 V/H/D + 整列整行扩展 + `NODE_BASE` |
| R21 AUD-138 / R22 续 | 框尺寸与内部列数必须同一数学；R22 落地 `subprocessInnerGrid` |

**评估要件**：框是整数倍格**不够**；框内必须是外层 3×3 / 走廊 / 端口 / 正交布线的缩放实例，而不是另一套「缩略图」。

## 2. 缺陷 A · 出入口同源（AUD-147 / 148，P0）

### 2.1 截图对应的几何事实（按「侧 / 口」计，不是按节点收成一处）

canonical 并行网关 `p1`（物理/化学并行检测）度数 4：入 = `g1` 合规 + `d1` 检测数据集；出 = `w3` 物理检测 + `w4` 化学检测。
LIVE ENGINE 截图上能直接指出来的同源口如下。硬 A1 = 同一侧既有入边又有出边；其余是共线搭乘 / 同入共点，观感同样是「一个口进出」，但红线口径不同。

| # | 截图位置 | 入 | 出 | 共点 / 几何 | 口径 |
|:--:|:--|:--|:--|:--|:--|
| 1 | **p1 右边**（菱形 ↔ 检测数据集） | `d1→p1` 虚线，箭头指进菱形右缘 | `p1→w3`「物理检测」从同一点出 | **(453, 267)** | **硬 A1** |
| 2 | **p1 底边**（两菱形之间的竖线根） | `g1→p1`「合规」从下进底边中点 | `p1→w4`「化学检测」从同一点出再右转 | **(391, 294)** | **硬 A1** |
| 3 | **两菱形之间的竖走廊** | 「合规」整段占用 `x=391, y=294→520` | 「化学检测」首段搭乘 `x=391, y=294→480`（重叠 **186px**）再右转 | 同一条竖线既当入又当出的延长 | 共线搭乘，把 #2 放大成走廊里的第三处 |
| 4 | **p1 右侧走廊** | 另有 `w2→g1` 竖线贴着菱形右边下行（`x=492`），再折入 `g1` 右缘 | 与 #1 的虚线入 / 物理检出挤同一侧走廊 | 三条线抢 p1 右侧 | 不是第三处 A1（该竖线并不贴 p1 端口），但是截图上「右边什么都往外接」 |
| 5 | **w8 左边**（编制批次报告） | `w3→w8` 与 `w4→w8` **同入 L** | 无出 | **(874, 547)** 同入共点 | **同入复用，红线允许**；截图仍是「一个口两根线」 |
| 6 | **w8 上下** | `sub1→w8` 从底进（`B`） | `w8→w9` 从顶出（`T`） | 同 `x=934` 一条竖线对侧穿过 | **A1 合法**（对侧），竖线看起来像穿盒 |

`p1` 占用：`IN={B,R} ∩ OUT={R,B} = {B,R}` —— **一个节点两侧都既入又出，截图上就是 #1 和 #2 两处**。`getPortMidpoint` 每侧只有几何中点，两条边共享同一像素，箭头层再用 `drawnInArrows = ${to}_${tp}` 去重。

**不是既入又出、避免再误诊的**：`g1`（质量指标是否合规?）`IN={R} OUT={T,B}`，右边只有「录入工艺参数」打入，顶出合规、底出不合规，A1 完好。截图上 `g1` 右边那支箭头容易和 p1 右侧那一团（#1+#4）看成一处，其实是另一条边的终点。

### 2.2 贪心初值 vs 坐标下降（破坏发生在哪一层）

| 分配器 | `p1` IN | `p1` OUT | A1 | 同向复用 |
|:--|:--|:--|:--:|:--|
| `solveAlgebraicPorts`（硬 skip） | `[B,B]` | `[R,R]` | **守住** | 同入 B×2、同出 R×2 —— **红线允许** |
| `optimizePorts` + `relaxNodes` | `[B,R]` | `[R,B]` | **打破** | 把合法的同向复用拆成非法的同侧入出 |

`w8`（编制批次报告，非网关）`IN=[L,L,B,R] OUT=[T]`，A1 完好，`L×2` 是合法同入。截图上「物理指标 / 化学指标」两线汇入报告左侧，语义清楚。

### 2.3 根因：R22 把从句安错

设计原文（`FLOW_ROUTING_ENGINE_DESIGN.md` §1.2）：

> `in(n) ∩ out(n) = ∅`，**且**每个端口至多服务一条边（**除非**汇聚/发散节点允许复用）

两个合取项：

| # | 约束 | 「除非」是否适用 |
|:--:|:--|:--|
| 1 | `in ∩ out = ∅` | **否**（A1，红线） |
| 2 | 每端口至多一条边 | **是**（A3 同向复用；网关扇入扇出需要） |

`PortOptimizer.ts:141-145` 写成：白名单节点「入/出可复用同侧端口」，循环里 `inAtFrom` / `outAtTo` 直接 `undefined`。等于约束 1 和 2 一起关掉。

R22 的动机（`g1` 在 `p1` 正下方、`p1` 出边也朝下，硬互斥会逼出背向）是真几何压力，但**合法出口已经存在**：贪心把两入都放 B、两出都放 R。代价是 `d1` 不走 0 折弯水平线、`p1→w4` 多 1 个弯。——这正是「A1 ≫ 折弯」该付的代价。坐标下降用 `costOf = bends + 1000×backFacing`、A1 对网关既不 skip 也不罚，0 折弯的同侧入出必然胜出。

### 2.4 门禁漏洞（AUD-148）

`assert_flow_geometry.ts` G5：

```ts
if (t === 'exclusiveGateway' || t === 'parallelGateway') continue;
```

canonical 唯一的 A1 违规在 `p1`（并行网关），G5 绿。G3（无背向）也绿，因为 `d1:L→p1:R` 与 `p1:B→w4:T` 朝向都「正确」——红线不在朝向，在单属性。

`assert_flow_svg.ts` 的 `a1-wsad` 仍只打贪心初值（R22 已承认脱节），所以初值守红线、渲染破红线，两套断言都看不见。

### 2.5 为何「流程图会没有意义」

A1 的语义不是美学：一侧 = 一种角色（只进或只出）。菱形右边同时接到「检测数据集（入）」和「物理检测（出）」时，读者无法从接触点读出因果方向，只能靠线型（虚/实）和远处标签猜。这与 BPMN「网关端口有方向」和本组件「城门口箭头只画 IN」（A2/A3）直接冲突——同一中点既要接无箭头的 OUT stub，又要接有箭头的 IN。

## 3. 缺陷 B · 子流程不是同一套范式（AUD-149 / 150 / 151，P1）

### 3.1 外层范式（①②③④）在框内缺了什么

| 外层（`computeExcelLayout` + 混合内核） | 子流程内部（`renderSubprocessInner`） |
|:--|:--|
| 3×3 绘制格，四周 `half=34` 走廊 | 无走廊；`pad=10` 后把剩余矩形均分 |
| 节点居中于绘制格，尺寸 ≥ `NODE_BASE` | 迷你盒 `iw=min(72, cellW-8)`、`miniH=min(20, max(12, cellH-8))`，与 `NODE_BASE` 无关 |
| WSAD 端口 = 边几何中点，首末段法向 | **无端口**；连线走节点中心 |
| `solveRouteHybrid` 正交避障 | 固定模板 `M s L s.x,midY L t.x,midY L t` |
| `CellOrder` + vh（缺省 V） | 声明序 `i % cols` |
| 内部节点是布局公民 | `s1/s2` 的 `cell=null`，**不进 `nodePos`** |
| 标题在节点盒内换行 | 标题钉在框**左下角**，与左格内部节点抢高度 |

R22 的 `subprocessInnerGrid` 只让「框 = cols×140 × rows×48」与「内部按 cols×rows 铺心」共用一个 `(cols,rows)`。这是**计数同构**，不是**几何同构**。前提②要的是缩放后的流程节点（仍有走廊、端口、A1），不是计数对齐的缩略图。

### 3.2 实测（同一 canonical）

```
sub1  W=280 H=48  at (666.2, 817.4)   ← 与 w5 同交叉格 (ri=3,ci=2)，缺省 vh=V 纵向叠
w5    W=120 H=44  at (666.2, 677.4)
rowHpx[3] = 280   ← ③ 整行扩展被 ny=2 撑高（这一层是对的）
colWpx[2] = 348   ← 被 W=280 的框撑宽（这一层也是对的）
s1/s2 不在 nodePos
迷你路径：M601.18,817.4 L601.18,817.4 L731.18,817.4 L731.18,817.4
```

同行两内部节点 `s.y === t.y === 框心 y`，模板仍走「经 midY」的四段，首末 stub 零长，水平段**穿过两个迷你节点中心**，并与左下角标题「技术中心复核」同高度。截图里几乎只看见右格「出具意见」，左格「受理复核」被标题吃掉 —— 不是内容缺失（SVG 文本里两个 label 都在），是**标题带没有从整数倍格里单列出来**。

### 3.3 用错了 `Layout`（AUD-151）

`subprocessInnerGrid`：`data.layout !== 'V'` → 横排。文档级 `Layout: H` 的意思是「D 为行、P 为列」（AUD-127：Location 维度与 Layout 无关），**不是**「子流程孩子从左到右」。内图 `s1 → s2` 是一条顺序流，应按格内拓扑 / vh / 内边方向排，与外层 `CellOrder` 同一套，而不是借用整图 Layout。

G4 断言只锁框的 `W/H` 和迷你字号 ≥ 11，**不锁**内部是否有走廊、端口、非退化路径、标题是否侵入格。所以 R22 门禁对「未遵循同一套范式」再次看不见。

## 6. 建议（按红线优先）

### 6.1 P0 · 把 A1 还给所有节点（含网关）

1. **删掉「A1 对网关关闭」**。`relaxNodes` 若保留，只能用于约束 2（同侧多条同向边），不能让 `inAtFrom` / `outAtTo` 变 `undefined`。
2. `optimizePorts` 对**所有**节点：`sp ∈ in(from)` 或 `tp ∈ out(to)` 的候选直接 skip（与贪心同一口径）。
3. 代价函数**不要**把 A1 做成可被 0 折弯买掉的罚；背向才是软罚。
4. 门禁：G5 改为**全节点** `in ∩ out = ∅`（网关不豁免）。另增「同向复用次数」作为质量信息，不失败。
5. 注入回归：把当前 canonical 的 `p1:B/R` 同侧入出作为必红用例（R22 注入 B 的反面）。

预期：canonical 回到贪心占用 `p1 IN=B×2 OUT=R×2`。截图上菱形右边不再既接虚线又接「物理检测」；底边不再既接「合规」又接「化学检测」。`d1→p1` 可能不再是 807px 水平 0 弯——这是红线该收的代价。

### 6.2 P1 · 子流程改走同一套 3×3，而不是再调缩略参数

不要继续在 `miniH` / `fs` / `pad` 上打补丁。最小同构：

1. 框内嵌一套局部 `computeExcelLayout`（或抽「绘制格几何」纯函数）：内部节点占 `NODE_BASE` 缩放格，四周留 `half'` 走廊，端点在边中点。
2. 内部边走 `solveRouteHybrid`（或至少 `getPortMidpoint` + 正交），禁止中心穿心。
3. 标题占**独立标题带**（类似外层 `titleH`），从 `rows×48` 里划出，不与内部格重叠。
4. 内部排列用 `CellOrder` / 内边拓扑，**禁止**用文档级 `Layout` 当铺排方向。
5. G4 增补：内部路径非退化（无零长 stub）、内部端点贴迷你节点边、标题盒与内部节点盒不相交。

### 6.3 P2 · 同向复用的视觉（非红线）

评估文档 M1：同侧 k 条边沿该边做 `i/(k+1)` 槽位，避免共点。这是 A3 的可视化，**不是**拆开 A1 的借口。可与 D5 VPSC 叠线治理一起做。

### 6.4 不要做的

- 不要为了 0 折弯或「箭头好看」再开 A1 白名单。
- 不要把 DOC 虚线（`d1`）从端口分配里拿掉——它也是入边，占 A1 名额。
- 不要把 `drawnInArrows` 去重当成「同侧入出合法」的证据；它只服务 A3。
- 不要在子流程里继续维护第二套连线模板。
