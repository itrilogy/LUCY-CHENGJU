## 一、63566cf 连线逻辑回溯（用户认可的"原设计正确基线"）

### 1.1 关键实现
| 部件 | 63566cf 实现 | 说明 |
|:---|:---|:---|
| `portXY` | 端点 = `±W/2 + L.half/2`（**走廊中线**，距节点边 half/2=17px） | 端点在 0.5 走廊中线，不贴节点边 |
| `targetCandidates` | `= sourceCandidates(b, a)`（原样复用源候选） | 目标端口朝向按"源候选"推导 |
| `pickPort` | usedSet=usedIn/usedOut；空则首位；全占复用首位 | 允许同侧复用 |
| 两趟分配 | 第一趟入口(`pickPort(b,targetCandidates(b,a),false)`)，第二趟出口(优先未出入口,fallback未出) | 先入后出 |
| `buildRoute` | L型/U型/Z型 + 去零长共线 | 正交最简 |
| 避障 while | tryOrder 同行下移/同列右移/扩格,MAX_ROUND=3,dw=L.half | 确定性避障 |
| 标签/箭头 | 标签最长线段中点；`marker-end` | 箭头有向 |

### 1.2 为什么 63566cf "合理"
- 端点走**走廊中线**（0.5 连线区），连线沿**格子通道**走——这正是"连线不贴节点、走走廊"的设计意图（避免连线压节点、与节点视觉分离）。
- 两趟分配（先入后出）+ 出口避开入口，实现"出入口互斥"。
- 避障确定性（同行下移→同列右移→扩格），无随机。

## 三、N/DATA 独立泳道 + 横向对齐 + 避障扩展格（用户洞察1）

### 3.1 设计
**N/DATA 不再是"依附漂移"，而是独立泳道里的普通流程节点。**

1. **独立泳道（Doc/Meta 文档泳道）**：在泳道网格**最右侧新增一列 `Doc`**（文档信息泳道），宽度 = max(N/DATA 节点宽 + 2×half)。
   - 所有 annotation(+dataObject) 落入该 Doc 列；它们**作为主网格节点**参与 ③ 扩展格。
2. **与主依附节点横向对齐（避障扩展格实现）**：
   - N/DATA 在 Doc 列中**占据与主依附节点相同的行**（行对齐）。
   - 若某行有**多个 N/DATA**，则它们按 ③ 避障扩展格纵向排开（ny 增大），并推动所在行的行高（`行高=该行最大ny×(H+2half)`）——N/DATA 作为节点参与避让，**必然产生与依附节点的横向对齐**。
3. **虚线虚拟连线**：N/DATA → 主依附节点用**虚线（dasharray）**表示"依赖/文档信息"（非普通流程实线），落附节点边界。

### 3.2 算法（扩展格避让，自洽）
```
// 布局（computeExcelLayout）
- Doc 列 = 第 nC 列（新增）
- N/DATA 节点 assign 到 (依附行, Doc列)，按附 attach 目标的行
- 同格多个 N/DATA → 按 vh 链排（ny 增），推动行高 = max(ny)*(H+2half)   ← 扩展格避让生效
// 连线（回归 63566cf 两趟分配 + 避障 while）
- N/DATA→依附 用虚线（dasharray "4 4"），走走廊中线，端点 = 节点边（或走廊中线，见下文待定）
```

### 3.3 端口端点待定点（需用户定）
- 用户洞察2 说 63566cf 合理（端点=走廊中线）。但洞察1 希望"N/DATA 与依附节点横向对齐 + 虚线连接"。这两者并行：
  - **普通流程连线**：回归 63566cf（端点走廊中线）。
  - **N/DATA 虚拟虚线连线**：端点贴节点边 或 走廊中线？——建议**贴节点边**（虚线表示依赖，箭头贴边更清晰），普通边走走廊中线。待用户确认。
