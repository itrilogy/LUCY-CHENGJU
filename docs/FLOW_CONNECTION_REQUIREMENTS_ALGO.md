# 第一部分 · 需求目标阐述

## 1. 背景与问题
企业体系文件流程图（BPMN 子集，字典-索引范式）由**泳道交叉格矩阵**承载节点，节点间用**正交曼哈顿连线**。当前复杂图例下出现两类问题：

1. **连线绕行到画布边缘**（如 `初审→技术评审`、`商务谈判→商务条件达成?` 横穿整图到左/右边缘），视觉混乱、不达"连线走格子走廊"的设计目标。
2. **同侧出入口 / 箭头悬空**（已部分修复）。

## 2. 需求目标（明确、可验证）
**G1 连线走就近格子走廊**：每条连线的正交路径应走"网格内的就近走廊"，不绕到画布边缘；理想是折线最少、距离最短（L1）。
**G2 走廊被占时"让位"而非绕行**：当连线的首选走廊被其它节点（障碍）占据时，通过**障碍格正方向腾挪**（右侧阻→列下移、上方阻→行右移）清出走廊，而非避障绕外侧。
**G3 稀疏可接受**：腾挪导致节点间距变大（稀疏）是可接受的——**人类可读 + 机器可读**（数据不丢、语义不变），这正是"有限空间流程设计"的正确形态。
**G4 有限空间**：流程图范围**有限**（如 32×32 / 64×64），节点只在界内腾挪；网格边界即上限。
**G5 确定性 + 可回归**：算法确定性（无随机），保证收敛（不无限循环），现有 131 项断言可回归，不破坏既有"节点居中/不超格/子流程整数倍/N-DATA泳道"等已定行为。

## 3. 非目标（明确不做）
- 不做 BPMN import（反向）、多画布编排。
- 不追求"节点绝对紧凑"（稀疏受许可，见 G3）。
- 不改动核心网格公式（③整行/整列统一扩展、节点居中）——腾挪是**在其后的位移调整**，非重写布局主干。

# 第二部分 · 数学方法需求描述

实现本办法所需的**数学工具/性质**，逐条给出（含为什么需要、判定标准）：

## M1 正交曼哈顿路径（L1）
- 连线路径 = 格子走廊上的**曼哈顿折线**，相邻点共 x 或共 y；端点贴节点边中点（IN 有箭头、OUT 无箭头）。
- **需求**：路径生成保证正交、无斜线；多段折线去零长共线。
- 判定：路径任一段 `dx=0 或 dy=0`。

## M2 折线数 + 距离的最优评估（目的地优先）
- 每条边选择入口/出口端口与路径时，按 **cost = 折线数 × w_bend + 曼哈顿距离 × w_len** 综合取最小。
- **需求**：折线数由 `sp/tp` 方向组合判定（同轴直线=0弯、L型=1弯、U/Z=2~3弯）；曼哈顿 = `|Δx|+|Δy|`。
- 判定：选到 **cost 最小** 的端口/路径组合。

## M3 出口方向：90 度象限内对应边（同向→上下向→反向）
- 源出口方向按目标相对位置：目标在源右上方→候选 `R,T`；按主导轴（`|Δx|≥|Δy|` → 水平；否则垂直）优先；上下向/左右向内部互斥（必有长短）。
- **需求**：把目标相对源的 8 象限映射到端口优先级 `[同向水平, 同向垂直, 反向垂直, 反向水平]`。
- 判定：主导轴方向优先、反向最后。

## M4 端口单属性（WSAD）
- 一个节点的 4 条边（W/S/A/D）各有 IN/OUT 单属性；**同侧不既入又出**（`usedIn ∩ usedOut = ∅`）。
- **需求**：两趟分配（先入口后出口），出口避开 `usedIn∪usedOut`；全占才降级。
- 判定：任意节点 `usedIn ∩ usedOut = ∅`。

## M5 障碍腾挪变换（正方向、整列/整行、单位=一绘制格）
- **右侧阻→列下移**：若横向走廊所在行 `r*` 右侧存在障碍列 `b(>c*)`，则 `{(r,c)|c=b, r≥r*}` 整列 `y += ph`（下移一绘制格）。
- **上方阻→行右移**：若纵向走廊所在列 `c*` 上方存在障碍行 `a(<r*)`，则 `{(r,c)|r=a, c≥c*}` 整行 `x += pw`（右移一绘制格）。
- 其中 `ph = 绘制格高 = 节点高 + 2×half`、`pw = 绘制格宽 = 节点宽 + 2×half`；**以左上位顶点 (0,0) 为基准**（下=+y、右=+x）。
- **需求**：腾挪以"列"或"行"为整体单位（含其下/其右），不破坏 ③"整行/整列统一扩展"；被腾挪节点重新居中于新绘制格（不重叠、不超格）。

## M6 收敛性（良基偏序 + 上界）
- 腾挪方向单调（只下、只右），节点坐标 `(x,y)` 在偏序 `(≤,≤)` 上单调不减、且因**有限网格（32/64）**而有一致上界 → 由**良基性**，任意执行序列**必然终止**（不无限循环）。
- **需求**：实现时不引入"向上/向左"的逆腾挪；总步数有界；达到稳定点。
- 判定：算法必然终止；稳定点无"可再按规则推进"的障碍。

## M7 可解性（有限空间 + 稀疏许可）
- 当每对端口间存在可穿越走廊（网格容量足够，且稀疏受许可）→ 可达 **Φ=0**（所有连线走 L1 就近走廊，无绕行）。
- 容量不足（某走廊被多方向完全堵死）→ 收敛到 `Φ=Φ_min`（最小可行绕行）——此时是空间限制，非算法失败。
- **需求**：以"有限网格 + 稀疏许可"为前提，不追求无限外扩。

## M8 最优性（局部 → 全局）
- 贪心单次腾挪：**局部最优**（每边不能单边更优）。
- 全局最优需 **③ 线路合并**（交汇且同目的地→合并，取**后续路程最短**）+ **⑤ 迭代调优**（Φ 不降时换腾挪/合并顺序重算）。
- **需求**：合并取"后程最短"（贪心最优）；迭代上限防死循环。
- 判定：Φ 不增且逐步趋近全局最小（在有限空间内）。

# 第三部分 · 算法说明（伪码，供实现）

## 0. 总流程（运输调运模型）
```
① 任一路线：按 exit(OUT)/enter(IN) 方向建初始正交路线
② 目的优先：各边选 cost 最小(bends*3 + dist*0.1) 的出入口
M3：出口取"90度象限对应边，同向→上下向→反向"
M4：端口单属性(同侧不既入又出)
③ 走廊让位(M5)：首选走廊被占→障碍列/行正方向腾挪一绘制格(稀疏可接受)
④ 线路合并：交汇且同目的地→合并后续，取后程最短
⑤ 城门口箭头：IN 端口渲染箭头(先划线后箭头,独立层)
⑥ 迭代(M6/M8)：Φ 不降时换腾挪/合并顺序重算,直至稳定
```

## 1. 走廊选择 + 腾挪（M2/M5 核心）
```
for e in edges:
  a,b = source,target
  # 首选走廊(M2): 按 M3 出口方向 + 目标象限, 定主导轴(横向/纵向走廊)
  if 走廊被占(其它节点盒在走廊内):
     if 横向走廊被右侧障碍占:  该障碍列(含r*下)整体 y+=ph   # M5 右侧阻→列下移
     if 纵向走廊被上方障碍占:  该障碍行(含c*右)整体 x+=pw   # M5 上方阻→行右移
     # 用腾挪后坐标重算该边路径
# 迭代(M6): 重复直到无"可再腾挪"的障碍(收敛)
```

## 2. 与现有实现的对接
- 在 `flowToSVG` 的 `nodeXY` 构建后，插入**腾挪预计算**（M5），更新 nodeXY 坐标；`nodeShape` 渲染也用腾挪后坐标（否则错位）。
- 现有已定行为（③扩展格/节点居中/子流程整数倍/N-DATA DOC泳道）**保持不变**，腾挪仅在其后位移。
- 迭代上界 = `max(8, edges×2)`（M6 防无限）。
